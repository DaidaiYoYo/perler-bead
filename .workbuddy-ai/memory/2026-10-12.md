# 2026-10-12

## 拼豆小游戏（首个完整版本）

从 Vite 脚手架空项目实现完整玩法，技术栈 Vue 3 + TS + Pinia + pinia-plugin-persistedstate。

### 文件结构

- `src/types.ts`：GameConfig / BoardData / GridSize
- `src/constants.ts`：难度档位（低100/中300/高500）、颜色预设（12/48/120）、上下限常量，以及 resolveLongestSide / resolveColorCount / resolveGridSize 三个纯函数
- `src/utils/color.ts`：中位切分法调色板（buildPalette）+ 红均值加权色差量化（quantizePixels）
- `src/utils/image.ts`：loadImage / readFileAsDataURL / shrinkImage（压缩到 1024 并填白底转 JPEG）/ samplePixels（按格子区域取平均色）/ renderEffect
- `src/stores/game.ts`：唯一 store
- `src/components/`：ConfigDialog、BeadBoard、ColorPalette、PreviewPanel
- 删除了脚手架残留 `src/router/index.ts`、`src/stores/counter.ts`，并移除 vue-router 依赖

### 关键决策

- **棋盘用 canvas 三层渲染**（底图格子 / 填色层 / 悬浮突起层）。500×375 = 18.75 万格，DOM 或 SVG 都不现实。
- **格子边长用小数 + 边界取整到设备像素**。最初用整数边长，高难度下 821px 可用高度只能取到 1px/格，棋盘缩到 500×375 白白浪费空间；改成 `cellSize = boardWidth / cols` 后再对每个格子 `Math.round(col * cellSize)` 取整，既铺满可用区域又没有缝隙。
- 按 cellSize 分档绘制：≥8 圆角格子+描边；2.5~8 细网格线；<2.5 纯色面板（此时单格不到 2.5 设备像素，画线只会糊成一片）。
- **填色数据用 `shallowRef<Uint8Array>`**，不参与响应式。原因：pinia 的 `$subscribe` 是 deep watch，数组每次写入都会触发全量序列化；`Uint8Array` 不是 plain object，Vue 的 `traverse` 会跳过它，所以必须在落笔结束时手动 `commit()`（自增 revision）来触发持久化。已在 vue 3.5.43 的 `traverse` 源码里确认这一点。
- 持久化用 `pick: ['config','board','cells','selectedColor','previewPos']` + 自定义 serializer（`Uint8Array` ↔ base64），落盘约 42KB（低难度）/ 326KB（高难度+120色）。
- 效果图（量化后的目标图）以 dataURL 存在 `board.effectUrl`，左上角预览图展示的就是它，点开按整数倍缩放 + `image-rendering: pixelated` 看单颗珠子。
- 拖拽填色用 Bresenham 补格，避免快速拖动跳格。

### 验证方式

本机没有 playwright 浏览器，用受管 node 工作区里已有的 `playwright-core` + 本机 Chrome（`executablePath`）跑真实浏览器冒烟测试，临时脚本与截图全部放在系统临时目录，跑完即删。覆盖：首次弹窗、拖拽上传、三档难度布局、表单越界与非 3 倍数校验、拖拽填色、刷新后数据恢复、预览放大与 ESC 关闭。无控制台报错。

## 交互改版：一个格子一个格子地选颜色

用户要求把玩法从「先选色再刷格子」改成「先点格子再选色」，并引入 gsap 做动画（后续动画都走 gsap）。

- 移除拖拽连续填色、移除底部常驻颜色面板。
- 新流程：点格子 → 格子高亮凸起（gsap `elastic.out` 驱动的弹入）+ 面板从底部滑出 → 点色块给该格子填色（面板保持）→ 点棋盘外空白取消选中、面板滑走。点另一个格子直接转移选中，面板不收起。
- store 变更：新增 `selectedCell`（不持久化），`selectColor`/`paint`/`commit` 三个 action 删除，改为 `selectCell(index|null)` + `applyColor(colorIndex)`；`revision` 的语义从「仅触发持久化」变成「触发持久化 + 画布重绘该格」。
- 选中格子仍复用悬浮层 canvas 绘制，未加 DOM 元素。
- gsap 坑：元素原本靠 CSS `transform: translateX(-50%)` 居中，gsap 一接管 transform 就会把它覆盖掉，改用 `xPercent: -50` 交给 gsap 管理；另外滑出用 `yPercent` 后滑入也必须回到 `yPercent: 0`，写成 `y: 0` 不会有任何动画。
- 视觉：选中高亮 = 蓝色外发光环 + 内侧白边 + 淡蓝底（`rgba(79,140,255,0.15)`）；悬停仍是轻量白色突起，两者可区分。

## 颜色编号与显示开关

- 颜色编号 = 调色板下标 + 1，正好等于 `cells` 里存的值（0 表示空），所以格子上直接画 `String(value)` 即可，不用另算映射。
- 文字颜色按底色明度选（`utils/color.ts` 的 `contrastColor`，亮度阈值 0.62），保证浅色块上是深字、深色块上是白字。
- 棋盘上的编号只在 `cellSize >= 12` 时绘制，字号 `round(cellSize * 0.46)` 并夹在 6~22px。低/中/高三档（8.2 / 2.7 / 1.6 px 一格）达不到阈值，只有自定义小格子（最长边约 75 以内）能显示——这是像素密度决定的，无法绕过。
- `showNumbers` 没有放进 `GameConfig`，而是 store 里的独立持久化字段。放配置里的话开关一变就要走 `generate()`，会连带把玩家已填的格子清空，这是不能接受的。
- 弹窗原来在 900px 高视口下会滚动，新增的开关被挤到滚动区外。压缩了原图预览（180→120px）、控件高度（42→40）、各处间距，并把 max-height 提到 820px，现在 622/622 正好不滚动。

## 工具栏：预览 / 下载 / 提示

设置按钮下方新增 `ToolBar.vue`（固定 top:72 right:20），点图标用 gsap 动画 `height: auto` + 逐项 stagger 垂直展开，用完某个工具自动收起。

- **补回了 `board.target`**（Uint8Array，每格正确颜色的调色板下标）。当初为了省 localStorage 没存它，提示功能必须要，只能加回来。体积代价：500 格存档从 326KB 涨到约 570KB。
- 兼容旧存档：`hasGame` 里加 `current.target instanceof Uint8Array` 判断，旧存档（无 target）会退回配置弹窗并回填原配置，不会白屏。
- **预览**：`renderCells()`（新增于 utils/image.ts）把 `cells` 渲染成 cols×rows 的画布，白底、不画编号，按整数倍缩放 + pixelated 展示。
- **下载**：同一个 `renderCells` 画布走 `toBlob` → objectURL → `<a download>`，文件名 `perler-bead-{cols}x{rows}.png`。objectURL 延迟 1s 再 revoke，立即 revoke 会打断下载。
- **提示**：新增第 4 层 canvas（hintCanvas，位于最上层），把 target 画上去，用 gsap `repeat: 5, yoyo: true` 让透明度 0→0.5→0 走满三个来回（6 次迭代才停在 0，`repeat: 2` 会停在 0.5）。期间 `store.hinting` 为 true，`selectCell`/`applyColor` 直接 return，指针事件也短路，光标变 not-allowed；玩家已填的数据全程不动，所以「恢复」是天然的。结束回调里 `gsap.set(opacity: 0)` 再 `finishHint()`。
- 闪烁节奏：`duration: 1` + `repeat: 5` + `yoyo` = 每轮（0→50%→0）2s、共 3 轮 6s。初版写的 `duration: 0.32`（每轮 0.64s）被反馈太快，改成 1s。用 gsap 的 `repeat/yoyo` 而不是 timeline 手动排 6 段，是这里最省事的写法。
- 提示层也走 `drawCellLabel`，编号 = target 值 + 1（target 存的是 0 基下标，和 `cells` 的 +1 编码不同，容易搞混）。因此提示层编号同样受「显示颜色编号」开关控制，与色板/棋盘保持一致。
